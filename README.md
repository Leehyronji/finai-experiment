# 상황 적응형 금융 AI 실험 자극물

KMAC 공모전 논문(Study 1·Study 2)의 온라인 실험 화면입니다. 모바일 뱅킹 앱을 모방한
정적 웹페이지이고, 빌드 과정이 없습니다. 실제 금전 거래는 일어나지 않으며 화면상의
모의 선택만 기록합니다. 화면에 나오는 은행명, 계좌번호, 기관명은 전부 가상입니다.

## 구성

- `index.html` 진입점
- `styles.css` 스타일
- `app.js` 화면 흐름, 응답 기록, 채점
- `data.js` 자극물 문구와 문항 데이터
- `.nojekyll` GitHub Pages가 파일을 그대로 서빙하게 하는 표시

Study 1은 예금 상품 비교 화면에서 정보 제시 방식을 4조건으로,
Study 2는 보이스피싱 의심 상황에서 AI 개입 수준을 5조건으로 조작합니다.
참가자는 두 연구 중 하나만 수행합니다.

## 실행

정적 호스팅에 위 파일을 루트에 올리면 끝입니다. `file://` 로 직접 열면 ES module
정책 때문에 동작하지 않으니 로컬에서는 서버를 띄워야 합니다.

```
npx serve .
```

## URL 파라미터

`study` 는 `1` 또는 `2`, `cond` 는 Study 1이 1~4, Study 2가 1~5입니다. 둘 다 생략하면
앱이 무작위로 배정합니다. 조건까지 고정해서 배포하려면 `?study=2&cond=4` 처럼 붙입니다.

응답을 서버로 받으려면 `endpoint` 에 POST를 받는 주소를 넘깁니다. Google Apps Script
웹앱, Supabase Edge Function, 자체 서버 모두 가능합니다. 설정 방법은
`데이터수집_설정.md` 에 정리해 두었습니다.

제출 뒤 설문 플랫폼으로 돌려보내려면 `redirect` 에 복귀 주소를 넣습니다. 완료 코드와
전송 성공 여부가 `?code=`, `&ok=` 로 붙어서 돌아갑니다. Prolific 을 쓰면
`PROLIFIC_PID`, `STUDY_ID`, `SESSION_ID` 가 그대로 기록됩니다.

`admin=1` 은 단계를 건너뛰는 개발용 바를 띄웁니다. 본조사 링크에는 절대 넣지 마세요.

## 기록되는 값

조건, 응답 문항, 화면별 체류시간, 첫 클릭까지의 반응시간, 선택 변경 횟수,
두 상품을 모두 열어봤는지, 행동 선택지의 제시 순서, 기기 유형과 화면 크기가 남습니다.
사후설명에서 자료 활용 재동의를 거부하면 응답 본문은 전송되지 않고 철회 사실만 남습니다.
